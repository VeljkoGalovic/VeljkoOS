# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

VeljkoOS Core API — an async FastAPI + PostgreSQL backend for goals, tasks,
learning sessions, and daily planning. The planner is the reason the service
exists; the CRUD endpoints are the substrate it reads from.

## Commands

```bash
docker compose up --build            # full stack; migrations auto-apply
docker compose down -v               # teardown incl. volume
docker compose logs -f api

alembic upgrade head                 # apply migrations
alembic revision --autogenerate -m "msg"
alembic check                        # fail if models have drifted from schema
uvicorn app.main:app --reload        # local run, needs reachable Postgres
```

There is no test suite or linter configured. `alembic check` is the closest
thing to a correctness gate — it diffs `Base.metadata` against the live schema.

**This machine has no `docker`.** It has `podman` 5.8.4 with no compose
provider, so `docker compose` will not run here. `podman build -t veljkoos-api .`
builds the image, and individual containers can be wired manually on a
`podman network`. Local Python is 3.14; the image targets 3.11, so prefer
verifying inside a container over a host venv (asyncpg wheel availability).

## Architecture

Requests flow `api/v1/*` → `services/` → `models/`, with `schemas/` defining the
contract at the edge. The layering matters in one place specifically:

**`services/planner_engine.py` is pure.** It takes ORM instances and a
`PlanRequest` and returns a `PlanResponse` — no session, no IO, no HTTP. The
route in `api/v1/planner.py` does all the querying and hands results over. Keep
it that way; the ranking rules are the part worth reasoning about in isolation.

Ranking precedence is `priority` (absolute — a P1 never sorts below a P2), then
goal urgency as tie-break, then duration with direction set by `energy_level`.
Energy caps the longest admitted task and flips duration ordering. Full tables
and the urgency formula are in [README.md](README.md#the-planner); don't
re-derive them from the code.

The planner is **read-only** — it returns a projection and never writes
`scheduled_for` back. Preserve that unless explicitly asked to add a
commit-the-plan endpoint.

## Non-obvious constraints

**`expire_on_commit=False` in `app/core/database.py` is load-bearing.** The
SQLAlchemy default expires attributes on commit; the next attribute read then
issues a lazy refresh, which is blocking IO and raises `MissingGreenlet` under
asyncio. Every route that commits and then serialises the ORM object depends on
this. Do not "clean it up".

**New models must be imported in `app/models/__init__.py`.** `alembic/env.py`
imports that package to populate `Base.metadata`. A model that isn't re-exported
there is silently absent from autogenerated migrations.

**`DATABASE_URL` host differs by context** — `db` inside compose (set in
`docker-compose.yml`), `localhost` in `.env.example`. The `postgresql+asyncpg://`
prefix is mandatory; the sync driver cannot drive the asyncio engine.

**The compose healthcheck gate is not decoration.** `api` waits on
`condition: service_healthy` so `alembic upgrade head` doesn't race Postgres
startup — the usual cause of a fresh `compose up` failing on connection refused.

**`GET /tasks` aliases its status filter.** The parameter is `status_filter`
with `alias="status"`, because a bare `status` would shadow the imported
`fastapi.status` used for the response codes in the same module.

Range constraints are deliberately duplicated — Pydantic `Field(ge=, le=)` at
the edge and `CHECK` constraints in the tables. Changing one means changing both.

## Skills scaffold

Predates the API and is unrelated to it. `.agents/skills/` is the real storage;
`.claude/skills/` holds symlinks into it, so one copy serves both Claude Code and
other agent tooling. `skills-lock.json` pins each skill to an upstream source —
its `computedHash` is *not* a plain digest of `SKILL.md` (`sha256sum` won't
match), so don't use it to test for drift.
